# BookSpace

Соціальна платформа для книголюбів: каталог книг, власна полиця, оцінки й відгуки, підписки на читачів, стрічка активності й сповіщення.
Навчальний проєкт з вебдизайну: клієнт (HTML, CSS, JavaScript) + сервер (Node.js, Express) + база даних (SQLite) + REST API.

- **Розгорнутий застосунок:** `https://ВАШ-САЙТ.onrender.com`  *(вставте після розгортання)*
- **Журнал взаємодії із ШІ:** [docs/AI_LOG.md](docs/AI_LOG.md) · **Початковий промпт:** [docs/PROMPT_START.md](docs/PROMPT_START.md)

## Можливості
Реєстрація та вхід · полиця зі статусами (хочу прочитати / читаю зараз / прочитано) · оцінка 1-5 для прочитаних книг (середній рейтинг рахує сервер) ·
відгуки (створення, редагування, видалення) · підписки на читачів і стрічка активності · сповіщення · редагування профілю · пошук, фільтр і сортування каталогу.

## Структура
```
bookspace/
├── public/            клієнт: *.html, css/, js/ (api.js, core.js, ui.js, nav.js, forms.js, ...), images/
├── server/            сервер
│   ├── index.js       запуск (читає .env, відкриває БД, сіє початкові дані)
│   ├── app.js         збирання Express-застосунку (middleware, маршрути, обробка помилок)
│   ├── config.js      налаштування зі змінних середовища
│   ├── db.js          підключення SQLite, схема таблиць, транзакції
│   ├── security.js    хешування паролів (scrypt), токени сесій
│   ├── auth.js        автентифікація (Bearer-токен)
│   ├── validate.js    перевірка вхідних даних
│   ├── rateLimit.js   обмеження частоти запитів
│   ├── seed.js        початкові дані (книги й демо-читачі)
│   ├── routes/        auth, me, books, reviews, shelf, readers, feed, notifications
│   └── test/          автотести REST API
├── docs/              промпт, журнал ШІ, діаграми
├── render.yaml        опис розгортання на Render
└── .env.example       приклад змінних середовища
```

## Запуск локально
Потрібен **Node.js 22 LTS** (https://nodejs.org). У терміналі з папки проєкту:
```bash
npm install
cp .env.example .env        # у Windows: copy .env.example .env  (за потреби відредагуйте)
npm start
```
Відкрийте **http://localhost:3000** (не відкривайте HTML-файли подвійним кліком: тоді запити до API не працюватимуть).
База даних створюється автоматично в `data/bookspace.db` разом із 9 книгами та 5 демо-читачами.

Корисні команди: `npm run dev` (перезапуск при змінах), `npm test` (автотести API), `npm run bench` (вимірювання швидкодії при запущеному сервері).

## Змінні середовища
| Змінна | Призначення |
|---|---|
| `PORT` | порт сервера (за замовчуванням 3000; на хостингу задається автоматично) |
| `NODE_ENV` | `production` вмикає суворі налаштування (HSTS, обов'язковий `SESSION_PEPPER`) |
| `SESSION_PEPPER` | **секрет** для захисту токенів сесій; у production обов'язковий |
| `DB_PATH` | шлях до файлу SQLite (за замовчуванням `data/bookspace.db`) |
| `SESSION_DAYS` | термін дії сесії в днях (7) |
| `CORS_ORIGIN` | дозволені джерела через кому (потрібно, лише якщо клієнт на іншому домені) |

Файл `.env` у Git **не потрапляє** (див. `.gitignore`). Секрети не зберігаються в коді.

## REST API
Усі відповіді - JSON. Помилки мають єдиний вигляд: `{ "error": { "code": "...", "message": "...", "fields": { "поле": "..." } } }`.
Захищені маршрути потребують заголовка `Authorization: Bearer <токен>` (токен повертають `register` і `login`).

| Метод і шлях | Опис | Доступ | Успіх |
|---|---|---|---|
| `GET /api/health` | стан сервера й БД | усі | 200 |
| `POST /api/auth/register` | реєстрація | усі | 201 |
| `POST /api/auth/login` | вхід | усі | 200 |
| `POST /api/auth/logout` | вихід (сесія знищується) | авторизовані | 204 |
| `GET /api/auth/me` | поточний користувач | авторизовані | 200 |
| `PATCH /api/me` | змінити ім'я / опис | авторизовані | 200 |
| `GET /api/me/summary` | статистика профілю | авторизовані | 200 |
| `GET /api/books?genre=&q=&sort=` | каталог (sort: title, author, rating) | усі | 200 |
| `GET /api/books/:slug` | книга, відгуки, стан користувача | усі | 200 |
| `PUT /api/books/:slug/rating` | поставити/змінити оцінку (лише прочитана книга) | авторизовані | 200 |
| `DELETE /api/books/:slug/rating` | прибрати оцінку | авторизовані | 200 |
| `POST /api/books/:slug/reviews` | написати відгук | авторизовані | 201 |
| `PUT /api/reviews/:id` | змінити свій відгук | власник | 200 |
| `DELETE /api/reviews/:id` | видалити свій відгук | власник | 204 |
| `GET /api/shelf` | моя полиця | авторизовані | 200 |
| `PUT /api/shelf/:slug` | додати книгу / змінити статус (`want`, `reading`, `read`) | авторизовані | 201 / 200 |
| `DELETE /api/shelf/:slug` | прибрати з полиці | авторизовані | 204 |
| `GET /api/readers`, `GET /api/readers/:id` | читачі та їхні полиці | авторизовані | 200 |
| `GET /api/readers/following` | на кого я підписаний | авторизовані | 200 |
| `PUT /api/readers/:id/follow` | підписатися | авторизовані | 200 |
| `DELETE /api/readers/:id/follow` | скасувати підписку | авторизовані | 200 |
| `GET /api/feed` | активність підписок | авторизовані | 200 |
| `GET /api/notifications`, `GET /api/notifications/unread-count` | сповіщення | авторизовані | 200 |
| `PATCH /api/notifications/:id`, `POST /api/notifications/read-all` | позначити прочитаними | авторизовані | 200 |

Коди помилок: `400 VALIDATION`/`BAD_JSON`, `401 UNAUTHORIZED`/`BAD_CREDENTIALS`, `403 FORBIDDEN`, `404 NOT_FOUND`, `409 EMAIL_TAKEN`/`REVIEW_EXISTS`/`NOT_READ`, `413 TOO_LARGE`, `429 RATE_LIMIT`, `500 INTERNAL`.

## Безпека
- Паролі: **scrypt** із унікальною сіллю, порівняння без витоку часу; однакове повідомлення про помилку входу для неіснуючої пошти й неправильного пароля.
- Сесії: випадковий токен (256 біт); у БД зберігається лише його HMAC із секретом `SESSION_PEPPER`; вихід знищує сесію; термін дії обмежений.
- База даних: **лише підготовлені запити** (захист від SQL-ін'єкцій), зовнішні ключі й обмеження CHECK, транзакції для зв'язаних змін.
- Перевірка всіх вхідних даних на сервері; права власника (відгук можна змінити лише автору); ліміт тіла запиту 10 КБ; обмеження частоти спроб входу.
- Заголовки: Content-Security-Policy, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy, HSTS (production). Клієнт екранує текст користувачів перед виведенням.
- Секрети лише в змінних середовища; службові файли (`server/`, `.env`, БД) не віддаються як статика.

## Розгортання на Render (безкоштовний тариф)
1. Завантажте проєкт у **новий** репозиторій GitHub (див. нижче).
2. На https://render.com: **New → Web Service** → виберіть репозиторій. Налаштування: Runtime **Node**, Build Command `npm install`, Start Command `npm start`, Health Check Path `/api/health`.
3. У розділі **Environment** додайте: `NODE_ENV = production`, `NODE_VERSION = 22`, `SESSION_PEPPER` = довгий випадковий рядок (`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`).
   (Або створіть сервіс через **Blueprint** - `render.yaml` уже є в репозиторії; `SESSION_PEPPER` тоді згенерується сам.)
4. Натисніть **Create Web Service**. Через кілька хвилин сайт буде за адресою `https://<назва>.onrender.com`.

**Публікація на GitHub (термінал):**
```bash
git init
git add .
git commit -m "ПР5: сервер Express, SQLite, REST API, клієнт на fetch"
git branch -M main
git remote add origin https://github.com/<ваш-логін>/bookspace-fullstack.git
git push -u origin main
```
*(Репозиторій спершу створіть на github.com порожнім, без README.)*

**Обмеження безкоштовного тарифу:** сервіс «засинає» після періоду бездіяльності (перший запит триває ~30-60 с), а файлова система тимчасова: **база SQLite скидається при перезапуску чи новому розгортанні** (початкові дані створюються знову). Для постійного зберігання потрібен диск Render (платно) або зовнішня БД.
